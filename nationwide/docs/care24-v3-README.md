## 운영본을 정리한 방법

PC의 최신 파일을 그대로 운영본이라고 간주하지 않았습니다. 서버와 다른 공개 파일은 당시 배포 묶음에서 가져오고, 묶음과도 다른 교육 HTML·실습 JS는 서버에서 읽기만 하여 가져왔습니다. 경로·출처·지문은 `deploy/public-file-provenance.json`에 있습니다.

두 React 소스의 교육 메뉴 문구 3개는 서버의 배포 당시 문구로 복원했습니다. 기존 로컬 빌드의 해당 서버 JS에서 이 문구들을 되돌리면 운영 서버 JS와 바이트 단위로 일치함을 확인했습니다. 상세 확인 범위는 `deploy/PROVENANCE.md`에 기록했습니다.

## 실행과 인계 범위

웹: Node.js 22.13 이상에서 `cd web`, `npm ci`, `npm run build`, `npm run start` 순서입니다. 실제 로그인·자료 저장은 별도로 전달받은 서버 환경·DB·암호화 키·업로드 저장소가 필요합니다. 운영 비밀값을 이 저장소에 넣지 마세요.

Android: Android Studio에서 `android/`를 여세요. 설정과 배포 주의사항은 `android/README.md`를 확인하세요.

사용자 요청에 따라 **모든 `.sql` 파일을 제외**했습니다. 기존 파일에는 DB 백업뿐 아니라 빈 DB의 구조를 만드는 SQL도 있었으므로, 이 저장소만으로 새 DB를 자동 생성하는 절차는 완성되지 않았습니다. TypeScript DB 구조는 `web/db/schema.ts`에 있습니다. SQL 제외를 우회해 다른 확장자로 복사하지 않았습니다. 도근 님이 별도 승인 후 빈 DB 초기화 방법을 정해야 합니다.

기존 PC 전용 Sites 실행 스크립트에 의존하던 설치·lint 명령을 일반 npm/ESLint 명령으로 정리했고, 포함되지 않은 DB 초기화 스크립트 명령은 제거했습니다. 테스트의 고정 비밀번호는 실행 시 생성하도록 변경했습니다. 업무 기능 변경은 하지 않았습니다.

DNS, nginx, systemd, service.env, assetlinks.json, 인증서, 운영 DB는 변경하지 않았습니다. Play Console도 사용하지 않았습니다.
